# AIConversationManager — 功能规格说明

## 项目目标

一个本地运行的 AI 聊天记录管理软件。把分散在各个 AI 平台上的对话导出、集中存入数据库，通过一个专门设计的界面浏览、管理这些记录——尤其是让冗长对话中不重要的部分可以被隐藏，只留下真正有价值的内容。

## 数据来源

- 不做浏览器扩展式的实时抓取，而是让用户使用各 AI 平台**自带的导出功能**，下载官方导出的 ZIP 文件
- 用户在软件的上传页面提交这个 ZIP，程序解析后写入数据库
- 支持重复上传：每次上传新的 ZIP/JSON，程序按会话增量同步
    - 使用 upsert 操作避免重复创建记录
    - 用户手动设置的 `hidden` 状态在重新导入时会被保留，不会被覆盖
    - 仅更新会话标题和消息内容，保持用户的管理状态不变

## 支持平台

- ChatGPT
- Gemini
- Claude
- DeepSeek

每个平台的导出格式不同，通过独立的 Parser 分别处理，统一转换成程序内部通用的 Conversation / Message 数据结构后再存库。

## 核心功能

1. **导入**：上传 ZIP → 按平台选择对应 Parser 解析 → 写入数据库（增量）
2. **浏览**：左侧栏显示会话列表，右侧主区域显示选中会话的完整内容
3. **管理**：用户可以自由隐藏会话中的部分内容（比如一段没用的闲聊），隐藏状态持久化保存，下次打开时保持

## 界面结构

- 登录页（当前阶段无真实账号系统，点击后直接跳转到主页）
- MyPage（主页）：左侧会话列表 + 右侧内容展示区，左侧栏顶部有跳转到"上传页面"的入口
- 上传页：选择 ZIP 文件并提交

## 技术架构

- **前端**：React + TypeScript + Vite + marked(Markdown解析) + DOMPurify(XSS防护)
- **后端**：NestJS + Prisma ORM v7
- **数据库**：SQLite（本地文件型数据库，无需单独安装数据库服务）
- **数据库模型**：
  - `Conversation` 表：存储会话基本信息，包含 `hidden` 字段标记是否隐藏
  - `Message` 表：存储消息内容，同样包含 `hidden` 字段支持消息级隐藏
- **后端模块划分**：
  - `conversation` 模块 —— 内含 4 个平台专属 Parser(chatgpt / gemini / claude / deepseek)，统一接口实现多平台解析扩展
  - `prisma` 模块 —— 数据库服务封装
  - `user` 模块 —— 暂缓开发，当前无账号系统
- **前端关键特性**：
  - 会话详情缓存机制，避免重复请求
  - 乐观更新UI，提升交互体验（操作失败自动回滚）
  - 完整的筛选功能：平台过滤、日期范围过滤、隐藏内容过滤

## 当前阶段不做的事(Out of scope)

- 用户账号注册 / 登录认证
- 云端部署、多用户
- 与 AIChatFolders 浏览器扩展的直接技术整合

## 未来可能的方向（仅记录构想，非当前计划）

- 如果自用效果好、有更多人想用，考虑部署到 AWS，加上账号注册系统支持多用户
- 如果做了 Web 版本 + 账号系统，AIChatFolders 扩展也可以复用同一套后端账号体系
